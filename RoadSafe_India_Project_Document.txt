## 1. Project Overview

**RoadSafe India** is a web-based AI system that predicts road accident risk across Indian highways using a multi-model ensemble approach. It combines **symbolic AI (Prolog-style First Order Logic)**, **probabilistic AI (Bayesian Networks)**, **unsupervised machine learning (PCA + K-Means clustering)**, **stochastic simulations (Monte Carlo)**, and **graph-based pathfinding (BFS)** to provide real-time accident hotspot predictions, route safety recommendations, and contextual driving advisories.

The system is trained conceptually on MoRTH (Ministry of Road Transport & Highways) dataset of **7,84,921 accident records from 2015–2022** across 28 Indian states and UTs.

**Live demo runs entirely client-side** — no server, no database. All state persists in `localStorage`.

---

## 2. Problem Statement & Motivation

India is ranked **#1 globally in road accident fatalities** (WHO 2023 Report):

| Statistic | Value |
|-----------|-------|
| Accidents per hour | **53** |
| Deaths in 2022 | **1,68,000+** |
| Annual economic loss | ₹1.47 lakh crore (~1.5% of GDP) |
| Identified Black-spots | **1,344** national highways |

Despite a comprehensive MoRTH reporting system (iRAD), there is **no publicly accessible real-time risk prediction tool** that a common driver can use. RoadSafe India fills this gap.

---

## 3. Objectives

1. **Predict** accident probability on any given Indian road segment with configurable conditions.
2. **Classify** risk into 4 levels: `EXTREME` / `HIGH` / `MODERATE` / `LOW`.
3. **Recommend** the safest route between any two Indian cities.
4. **Identify** known accident black-spots with death statistics on a predicted route.
5. **Visualize** AI model internals: Bayesian network CPTs, PCA scatter plots, FOL terminal, ROC curves, confusion matrix.
6. **Generate** downloadable PDF reports for offline use.
7. **Simulate** uncertainty distributions using Monte Carlo methods.
8. **Support** multi-user access with login/logout and per-user history.

## 7. AI Modules — Detailed Breakdown

### 7.1 Module 1: Prolog FOL Engine

**Location:** `app.js` — Lines 22–76

**Concept:** Mimics a Prolog-style **First Order Logic** rule engine using JavaScript. Each rule has a HEAD (conclusion) and BODY (list of conditions). The engine performs **unification**: it asserts facts from user inputs and checks which rules fire.

#### Rule Set (8 Rules)

| Rule | Head | Body Conditions | Severity |
|------|------|----------------|----------|
| R1 | `dangerous(Road)` | highway ∧ rain ∧ night | **EXTREME** |
| R2 | `dangerous(Road)` | poor_road ∧ high_speed | **HIGH** |
| R3 | `high_risk(Road)` | historical_accident_zone ∧ heavy_traffic | **HIGH** |
| R4 | `moderate_risk(Road)` | urban ∧ night ∧ heavy_traffic | **MODERATE** |
| R5 | `dangerous(Road)` | fog ∧ high_speed | **EXTREME** |
| R6 | `safe(Road)` | clear ∧ day ∧ good_road ∧ divider | **LOW** |
| R7 | `danger_zone(Road)` | festival ∧ highway ∧ night | **EXTREME** |
| R8 | `moderate_risk(Road)` | construction ∧ moderate_traffic | **MODERATE** |

#### Fact Building (`buildFacts()`)

User inputs are translated into a **fact set**:
```
Input: roadtype = "national_highway" → Fact: highway(Road)
Input: weather = "fog"              → Fact: weather(fog)
Input: timeofday = "night"          → Fact: time(night)
Input: speedlimit = "120"           → Fact: speed_limit(high)   [≥100]
Input: roadcondition = "poor"       → Fact: road_condition(poor)
Input: traffic = "jam"              → Fact: traffic(heavy)
Input: festival = true              → Fact: festival_season(true)
Input: accident_history = true      → Fact: historical_accident_zone(Road)
Input: divider = true               → Fact: divider(present)
```

#### Evaluation
```javascript
function evalFOL(inp) {
  const facts = buildFacts(inp);
  const fired = [], unfired = [];
  FOL_RULES.forEach(r =>
    (r.body.every(b => facts.has(b)) ? fired : unfired).push(r)
  );
  return { fired, unfired, facts };
}
```

#### FOL Terminal
A Prolog-like terminal UI shows:
- Rule loading (`:-` prefix)
- Fact assertion (`+` prefix)
- Unification results (`✓` / `✗`)
- Final verdict (`⚠` prefix)

### 7.2 Module 2: Bayesian Network

**Location:** `app.js` — Lines 78–114

**Concept:** A **Naïve Bayes classifier** with Conditional Probability Tables (CPTs) trained on 5.5 lakh MoRTH records.

#### Evidence Nodes (8)
| Node | Likelihood Ratio (LR) |
|------|----------------------|
| 🌧️ Rain | 2.8× |
| 🌫️ Fog | 3.4× |
| 🌙 Night Driving | 2.2× |
| 🛣️ Highway | 1.9× |
| 🕳️ Poor Road | 2.5× |
| 🚗 Heavy Traffic | 1.6× |
| 🎉 Festival | 2.1× |
| 🚧 No Divider | 1.4× |

#### Formula
```
P(Accident | Evidence) = BASE_RATE × ∏ LR[i]   for all active evidence i

BASE_RATE = 0.058  (5.8% per km per hour — MoRTH national average)
```

Each evidence node is treated as **binary** (probability > 0.5 = TRUE).

#### Sample CPT Table (shown in UI)
| Rain | Night | Highway | P(HIGH) |
|------|-------|---------|---------|
| Yes  | Yes   | Yes     | 0.73    |
| Yes  | Yes   | No      | 0.54    |
| Yes  | No    | Yes     | 0.48    |
| No   | Yes   | Yes     | 0.42    |
| No   | No    | No      | 0.11    |

#### Interactive Bayesian Dial
The UI renders a **semicircular gauge** that updates live as the user adjusts evidence sliders (0–100%). The arc goes green → yellow → red based on P(Accident).

### 7.4 Module 4: Monte Carlo Simulation

**Location:** `features.js` — Lines 125–163

**Concept:** Quantifies **uncertainty** in the Bayesian risk estimate by running N random simulations with Gaussian noise applied to all 8 evidence inputs. Produces a risk score distribution histogram.

#### Simulation Algorithm
```
For i = 1 to N (iterations):
  For each feature k:
    noisy_k = clip(base_k + Gaussian(0, σ), 0, 1)
    if noisy_k > 0.5: p = p × LR[k]
  results[i] = min(97, round(p × 100))

Plot histogram of results (10% buckets)
Report: mean, 5th–95th percentile CI, % extreme+high
```

#### User-Configurable Parameters
| Parameter | Options |
|-----------|---------|
| Scenario | High Risk / Moderate / Extreme / Low |
| Noise σ | 0.05 / 0.10 / 0.20 / 0.30 |
| Iterations N | 500 / 1,000 / 5,000 / 10,000 |

#### Output
- **Histogram chart** (color-coded: green→yellow→orange→red bins)
- **Mean risk score**
- **90% Confidence Interval** [P5, P95]
- **% of simulations** reaching EXTREME or HIGH risk

### 7.5 Module 5: Markov Chain (Hidden — commented in UI)

**Location:** `features.js` — Lines 165–212

> *Note: The Markov Chain section is currently **commented out** in `index.html` but the full JavaScript logic exists and is functional in `features.js`. It was disabled per project scope change, but the code is preserved.*

**Concept:** Models accident risk as a **4-state Markov process** through the 24-hour day cycle. Transition probabilities are derived from MoRTH time-of-day accident distributions.

#### States
`Low → Moderate → High → Extreme`

#### Transition Matrix (Expressway example)
```
         Low   Mod   High  Ext
Low    [ 0.60  0.25  0.10  0.05 ]
Mod    [ 0.20  0.50  0.20  0.10 ]
High   [ 0.10  0.20  0.50  0.20 ]
Ext    [ 0.05  0.15  0.30  0.50 ]
```

- Different matrices for: Expressway, National Highway, Urban Road
- `HOUR_ADJUST[]` array modulates transitions by time of day (night hours increase P(Extreme))
- Predicts **24-hour risk probability curve** from any start hour

### 7.6 Fusion Engine (Ensemble)

**Location:** `app.js` — Lines 196–243 (`runAnalysis()`)

**Formula:**
```
fScore = [0, 40, 65, 78, 90][min(firedRules, 4)]   // step-function from FOL
score  = round(fScore × 0.45 + bayesProb% × 0.55)
score  = clamp(score, 3, 97)
```

**Risk Level Assignment:**
```
if any fired rule has sev == "EXTREME" → EXTREME
else if any fired rule has sev == "HIGH"    → HIGH
else if score ≥ 60                          → HIGH
else if score ≥ 35                          → MODERATE
else                                        → LOW
```

| Fog | 3.4× |
| Dust Storm | 3.1× |
| Heavy Rain | 2.9× |
| Rain | 2.8× |
| Cloudy | 1.3× |

### BFS Pathfinding
```javascript
function bfsPath(adj, src, dst, excludeNodes=[]) {
  // Queue: [currentNode, pathSoFar, distanceSoFar, edgesSoFar]
  const q = [[src, [src], 0, []]];
  const seen = new Set([src]);
  while (q.length) {
    const [node, pth, dist, edgs] = q.shift();
    if (node === dst) return { nodes:pth, dist, edges:edgs };
    // Expand neighbors not already visited or excluded
    for (const nb of adj[node] || []) {
      if (!seen.has(nb.to) && !excludeNodes.includes(nb.to)) {
        seen.add(nb.to);
        q.push([nb.to, [...pth, nb.to], dist+nb.edge.dist, [...edgs, nb]]);
      }
    }
  }
  return null;
}
```

**Two routes found by:**
1. **Primary BFS** — shortest path
2. **Alternative BFS** — exclude an intermediate node from the primary path, forcing a different route

### City Normalization (normalizeCity)
```
Raw input → lowercase + strip non-alpha
    │
    ├── Check CITY_ALIASES (e.g., "bombay" → "mumbai")
    ├── Exact match in IG_NODES
    ├── Name match against IG_NODES city names
    ├── FUZZY_CITY_MAP (200+ Indian cities → nearest graph node)
    ├── Partial fuzzy map match (prefix-4)
    ├── Prefix-4 match against graph nodes
    └── Prefix-3 match against graph nodes
```

### Route Risk Scoring
```javascript
function pathRiskScore(edges, wVal, trafficVal) {
  let p = 0.058;  // base rate
  // Weighted sum over all edges by distance
  edges.forEach(e => {
    p += (0.058 × COND_SCORE[e.cond] × (e.risk/50)) × (e.dist/totalDist);
  });
  p *= WEATHER_MULT[wVal] × TRAFFIC_MULT[trafficVal];
  return clamp(round(p × 100), 4, 96);
}
```

- 12-city weather database with: temp, humidity, visibility, condition, wind, AQI, risk factor
- Adds ±6% random noise for "live" feel
- Visibility-based risk: < 3km = HIGH, < 6km = MODERATE, ≥ 6km = LOW
- **Auto-fills** the Analyzer weather dropdown

### Route Comparison (A vs B)
- Runs the FOL + Bayesian fusion on both routes independently
- Renders side-by-side risk scores with color-coded risk tags
- Bar chart comparing `['FOL Risk', 'Bayesian P(Acc)', 'Overall Score']` for both routes
- Declares the safer route

### Hotspot Database (10 cards)
Each card shows:
- Route name + NH reference + state
- Deaths/year + Accidents/year
- Dangerous conditions text
- Risk score bar (color-coded to severity)
- Clicking a card auto-fills the analyzer location dropdown

### PDF Report Generator
Uses **jsPDF** to create a multi-section A4 report:
1. Header with logo, date, analyst name
2. Analysis Summary (location, risk, score, weather, cluster, time)
3. FOL Rule Engine Results (fired rules + descriptions)
4. AI Model Architecture description
5. Per-model performance metrics
6. Safety Recommendations
7. Footer with attribution

### Knowledge Graph Visualizer
- SVG-based directed graph of FOL predicates
- 18 nodes (13 fact nodes + 5 conclusion nodes)
- 17 edges
- When an analysis fires rules, corresponding nodes and edges **glow in amber** with drop-shadow filter
- Nodes colored: blue (facts), red (dangerous), orange (high_risk/moderate_risk), green (safe)

### Analysis History
- Stored per-user in localStorage
- Columns: Location, Risk Level, Score, Weather, Road Type, Time, Date
- CSV export with all fields
- Refresh button to reload

## 16. Known Limitations & Future Work

### Current Limitations
| Limitation | Impact |
|-----------|--------|
| Static weather database (12 cities) | No real-time IMD API integration |
| No real GPS / live traffic | Traffic estimated from time-of-day only |
| Route DB only covers 10 city pairs in detail | BFS graph covers more but with less granularity |
| No map route drawing | Routes shown as text, not plotted on Leaflet map |
| Client-only (no server) | Cannot share analyses between users |
| Bayesian is naïve (assumes independence) | Real CPT dependencies not fully modelled |
| Markov chain is hidden / commented out | Temporal risk evolution not visible in UI |

### Potential Future Enhancements
1. **Real IMD Weather API** integration for live conditions
2. **Google Maps / OSRM** for actual road geometry and live traffic
3. **Deep Learning model** (LSTM or Transformer) for sequential accident prediction
4. **Backend server** (Node.js / Python FastAPI) for shared history and analytics
5. **Mobile app** (React Native) for driver-side alerts
6. **ISRO NAVIC** integration for Indian GPS data
7. **Polyline route drawing** on Leaflet map for BFS paths
8. **Push notifications** for high-risk alerts during navigation
